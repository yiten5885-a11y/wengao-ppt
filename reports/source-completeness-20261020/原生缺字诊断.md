## 2. 根因诊断（本机只读核对）

| 核对项 | 结果 |
|---|---|
| Microsoft YaHei 是否在本机 | **缺失**（/System/Library/Fonts、/Library/Fonts、~/Library/Fonts 均无） |
| Hiragino Sans GB / Avenir Next | 本机存在（/System/Library/Fonts） |
| 产品渲染路径 | 包内 `assets/fontconfig/fonts.conf` 把 Microsoft YaHei/微软雅黑 **强映射**到 Hiragino Sans GB（binding=strong），经 `FONTCONFIG_FILE` 在渲染子进程生效；`wengao_ppt/fontenv.py` 是唯一构造点 |
| 原生 GUI 直接打开 | 没有这层环境 → LibreOffice 自选替换字体不含中文字形 → 方框；**文本层/AX 不受影响**（所以"能打开、13 页、原文完整"与"缺字"同时成立） |

**结论**：不是文件损坏、不是 PowerPoint 兼容性问题，是**本机字体环境差异**：
声明字体 Microsoft YaHei 在本机不存在，渲染路径有显式映射、原生 GUI 路径没有。

## 3. 启动兼容路径（新增，项目可控范围）

新增 `scripts/open_native.sh <文件.pptx>`：用**与渲染子进程同一构造点**
（`wengao_ppt.fontenv.build_env()`）取有效字体配置后，以该环境启动本机
LibreOffice GUI 打开文件。边界与渲染路径一致：

- 只设本次进程环境变量（`FONTCONFIG_FILE` / `XDG_CACHE_HOME`）；
- 不写 /etc、不改用户 fontconfig、**不改全局 LibreOffice 设置**、不改系统 PATH；
- 不复制、不下载任何字体文件；被打开文件字节不变（SHA 保持 `e43dad9e…`）；
- 脚本本身不做任何点击/录屏——UI 操作归监督方（Cua）。
